# GA4ゲーム計測

測定ID: `G-V48HF21Y4C`。
HTTPSの `norikae-rush.jp` / `www.norikae-rush.jp` のみでGoogleタグを非同期ロードします。
localhost・CI・プレビュー用ドメイン・Capacitorのカスタムスキームではロードも送信キュー作成もしません。
既存HTML内のゲームスクリプトに追加し、画面デザインと4つのインラインスクリプト構成は維持しています。

| イベント | タイミング | パラメーター |
| --- | --- | --- |
| `page_view` | ページ読込時に1回 | 固定の `page_location` / `page_title` / 空の `page_referrer` |
| `game_start` | 1プレイの開始 | `game_mode` |
| `game_end` | プレイ終了・トップへ戻る | `game_mode`, `result`, `correct_count` |
| `result_share` | 結果シェアボタン操作 | 終了時点の `game_mode`, `result`, `correct_count` |

各イベントは `send_to` に測定IDを指定します。
`game_mode`: 初級=`beginner`、中級=`intermediate`、上級=`extreme`、ラッシュ=`rush`、バトル=`battle`。

`result`:
- 通常: 既存の結果ランクに合わせた `s_rank` / `a_rank` / `b_rank` / `c_rank` / `d_rank`。
- ラッシュ: `master`（100問達成）/ `wrong`（誤答）/ `timeout`。
- バトル: `win` / `loss`。1問ごとの正誤・時間切れは試合終了と区別し、終了イベントを送りません。
- 途中でトップへ戻った場合: `quit`。正解数はその時点で記録済みの正解数です。

バトルは勝敗確定の時点で記録し、その後の結果表示ボタン・演出・トップ遷移では重複させません。
ブラウザーやタブの強制終了・クラッシュは完走判定しません。

## 重複と失敗への対策

- GA4の自動ページビューを `send_page_view:false` で止め、明示的なページビューを1回送ります。
- 同じモードの開始処理が連続して呼ばれても、終了するまで開始イベントは1回です。
- 終了イベントは1プレイにつき1回。結果画面再描画やタイマー/手動操作の競合でも重複させません。
- シェアは同じプレイ結果につき1回。キャンセルを含むボタン操作の計測であり、SNSへの投稿成功や受信を意味しません。
  実際のシェア機能の再操作は制限しません。再プレイ後の結果は別に計測します。
- 計測呼び出しは同期例外・Promise拒否を処理します。タグのブロック・ネットワーク不通・壊れたキューでもゲームは続行します。
  計測の到達保証や失敗時の再送はせず、ゲームを計測結果待ちにしません。

## 送信内容とプライバシー

ゲームから渡すイベント値は、許可した固定のモード/結果と有限の整数だけです。
プレイヤー名、メール、ユーザーID、共有文言/画像、localStorageの中身、駅名などは送信しません。
ページURLは `https://norikae-rush.jp/` に固定し、クエリ・ハッシュ・参照元URLは渡しません。
Googleタグ読込時もreferrerを送らない設定にし、Google Signalsと広告パーソナライズを無効にしています。
GA4自体のCookieや通信時の技術情報の処理はGoogleの標準仕様に従います。アプリ側で個人データを追加しない設計です。

## 確認・運用

```bash
TEST_URL=http://127.0.0.1:8018 CHROMIUM_PATH=/usr/bin/chromium node --test tests/*.cjs
```

`tests/analytics.cjs` は本番と同じoriginをブラウザーで模擬し、Googleタグをスタブに置換します。
実際のGA4にテストのアクセスやゲーム結果を送信しません。全5モード、再描画/連打、再プレイ、共有、URL/保存データの非送信、
タグブロック、同期/非同期エラーを検証します。既存のpush/PR用CIがこのテストも自動実行します。

PR承認・本番反映後に、測定IDのプロパティでリアルタイム/DebugViewの受信を確認してください。
GA4管理画面では `game_mode` と `result` をイベントスコープのカスタムディメンション、`correct_count` をカスタム指標として
登録すると探索で利用できます。正解数を集計するときは `event_name=game_end` に絞り、結果情報を含む `result_share` と合算しないでください。この作業とGA4側の拡張計測設定の確認はプロパティ管理者が行います。
プロパティ側で別のタグや独自のフォーム/検索計測を追加する場合は、重複・個人情報がないか別途確認してください。
このPRではGoogle管理画面の変更や実データ受信確認は行っていません。
